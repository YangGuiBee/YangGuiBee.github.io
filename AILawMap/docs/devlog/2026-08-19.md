**x=752 열 (산업ㆍ연구 계열) 7개**: 중소기업기본법ㆍ소상공인기본법(원래 큐에 없던 법, 외부링크→로컬 전환)ㆍ벤처기업육성법ㆍ벤처투자촉진법(역시 신규)ㆍ정보통신진흥융합법ㆍ국가연구개발혁신법ㆍ과학기술기본법.

방법론은 기존과 동일: law.go.kr DRF(curl+OC=test) → Python 조문추출 스크립트 → 주체×7단계 절차구조도 설계 → Node.js 검증(EDGES/LEGAL_BASIS 무결성) → laws/ 배포 → index.html 갱신.

## 2. 반복 재발 버그 4종 근본수정 (공통 인프라 레벨)

사용자가 스크린샷으로 여러 차례 지적하면서 드러난, 이번 세션 이전부터 누적된 잠재 버그들.

- **시행령명 "시행령"만 표시**: `.law-current`/`.law-sibling`은 항상 전체 법령명+" 시행령"이어야 하는데, `law-sibling`(본법→시행령 링크) 쪽에서 반복 재발. 전수 스캔(`class="law-(sibling|current)"[^>]*>시행령<`)으로 6개 파일 발견(이 중 3개는 세션 훨씬 이전에 이미 push된 저작권법 계열 파일) — 기존 점검 스크립트가 law-current만 검사하고 law-sibling을 빠뜨린 게 원인이었음을 확인 후 점검 방식 자체를 수정.
- **카드 클릭 상세뷰 폰트/마크업 불일치**: `ai-basic-act.html` 표준 마크업(`wf-detail-body/side/main`)이 아니라 스타일 없는 자체 클래스로 새로 지어졌던 문제 → `build_pages.py`에 `show_detail_js()` 헬퍼 추가, 19개 파일 정규식 일괄 패치.
- **wf-node에 AI연결 초록(`ai-note`) 표시 누락**: 이전 세션들이 만든 26개 파일은 다 갖고 있던 관행인데, 이번 세션에 새로 만든 21개 법 전부에서 빠뜨림 → `build_grid_html()`에 `ai_ids` 파라미터 추가해 전체 재적용. 부수적으로 [1]구성 섹션의 초록 챕터 개수와 [2]절차구조도의 초록 노드 개수가 안 맞는 사례(민법 2개 vs 1개, 행정절차법 시행령 1개 vs 0개)도 발견해 같이 수정.
- **GATE_SUBS 미설정으로 엉뚱한 라벨 노출**: `build_pages.py`가 원래 먹는물관리법용으로 만들어진 모듈이라 그 기본값이 하드코딩돼 있었는데, `bp.GATE_NAMES`만 설정하고 `bp.GATE_SUBS`는 빠뜨린 4개 스크립트(형법ㆍ민법ㆍ행정조사기본법ㆍ행정절차법)에서 게이트 헤더에 "수질관리기준" 등 먹는물관리법 라벨이 그대로 노출되던 버그. `bp.GATE_SUBS = [g.split(" ", 1)[1] for g in GATE_NAMES]` 패턴으로 자동유도하도록 통일.

이 네 가지 모두 `feedback_lawmap_common_ui_rules`/`feedback_lawmap_decree_completeness_rule` 메모리에 근본원인과 재발방지 체크리스트로 기록.

## 3. "시행령이 있으면 무조건 만든다" 규칙 정립

행정조사기본법ㆍ행정절차법을 처음엔 "index.html이 원래 단일 박스로 설계됐다"는 이유로 시행령 없이 법 페이지만 만들었는데, 사용자가 "시행령이 실제로 부존재하나?"라고 질문 → 확인해보니 둘 다 실제로 시행령이 있었음(형법ㆍ민법만 진짜 없음). "공통규칙: 시행령이 있으면 모두 작성한다" 지시를 받아 두 시행령을 뒤늦게 제작하고, index.html 박스도 2줄 완료 스타일로 갱신.

## 4. 형법ㆍ민법 재작업 (간소패턴 → 표준 3단구조)

"일반법이라 절차가 없다"는 판단은 사용자가 승인한 예외가 아니라 임의 축소였다고 판단해 기각됨 — 방대한 법이라도 표준 [1]구성[2]절차구조도[3]관련법령을 유지하되, 범위를 좁혀서 타협:
- **형법**: 전체 구조(총칙+각칙42장)는 [1]구성에서 개관, [2]는 AI기본법 제41조가 준용하는 제7장(공무원의 직무에 관한 죄, 제122~135조)만 상세화. "행위 절차"가 아니라 "죄의 배열 구조"를 6주체(직무유기ㆍ직권남용형/인신구속수사관련/선거정보관련/뇌물수수/뇌물공여자/법원)×7단계로 구성.
- **민법**: 5편 개관 후 [2]는 AI기본법 제26조⑦이 준용하는 법인편(제31~97조, 설립→해산청산)과 AI법인격 논의에 쓰이는 성년후견(제9ㆍ10조)만 상세화. 3주체×7단계.

## 6. 국제규범 트랙 신규 완성 (10개 + 추가 4개 = 14개)

law.go.kr DRF API가 없는 완전히 새로운 영역이라, AskUserQuestion으로 "국내법과 동일한 풀 페이지" 방식 확인 후 진행.

**1차 10개**: EU AI Act(EUR-Lex 직접 WebFetch 안 됨→artificialintelligenceact.eu로 대체)ㆍGDPR(gdpr-info.eu)ㆍEU DSA(eu-digital-services-act.com)ㆍOECD AI원칙(oecd.ai, 선언문이라 "원칙구조도"로 명명)ㆍNIST AI RMF(airc.nist.gov, "기능구조도")ㆍISO/IEC 42001·23894(**유료표준, 원문 비인용** 공개요약만)ㆍUNESCO윤리권고("원칙구조도")ㆍCOE AI협약(공식원문 403 차단→법률자문사 2차자료로 대체, "절차구조도" 유지—법적구속력 있는 조약이므로)ㆍ미국AI행정명령(정권교체로 계속 바뀌는 특성상 [1]구성에 2019~2026 계보 타임라인 표시).

**사용자 추가요청 4개**("일단 이것까지만 추가해줘")**: 서울선언ㆍ프런티어AI안전서약(2024 한국ㆍ영국공동개최 — 한국개최 성과물이라 최우선순위)ㆍG7히로시마프로세스(11개 지침원칙, EY 정리자료로 verbatim 확보)ㆍUN AI결의안(2024, 193개국 컨센서스)ㆍ중국 생성형AI관리방안(2023, 중국최초 구속력있는 규정, "사회주의 핵심가치관 견지" 명시 — EU/미국과 전혀 다른 콘텐츠 가치관 통제 모델이라 비교가치 있음).

index.html 국제규범 열을 10→14개로 확장하며 SVG viewBox를 550→660으로 늘렸다가, 사용자가 "박스 세로크기 줄여서 한 페이지에" 요청 → 국제규범 14개 박스만 32px→24px, 간격 40→32px로 축소해 viewBox를 550으로 되돌림.

## 방법론 메모 (국제규범 전용, 다음에 재사용)

- 공식 1차 사이트(EUR-Lex, rm.coe.int, unesco.org, ISO)는 WebFetch가 빈 콘텐츠ㆍ403을 자주 반환 — 조문별로 잘 정리된 제3자 사이트를 WebSearch로 찾아 대체.
- `articleNum()`이 `build_pages.py` 공유 `JS_ENGINE`에 한국어 정규식으로 박혀있어서, 국제규범마다(Article N / Art. N / 절N / 가치N / EO조치명 등) `{{bp.JS_ENGINE}}` 삽입 직후 재선언 필요(JS는 나중 선언이 이김). **cite 문자열과 ARTICLES 딕셔너리 키가 정확히 일치하는지 항상 재확인**(불일치로 lookup 실패한 사례 2건 발생·수정: ISO23894 절6.4 중복cite, 미국EO/UN결의 identity-articleNum과 키 불일치).
- `bp.art_url()`/`bp.chapter_url()`/`bp.build_grid_html()`은 law.go.kr 전용 — 국제규범마다 자체 `art_url()` + 로컬 `build_grid_html()` 복제.
- 원문 신뢰도 4단계(verbatim/발췌요약/2차자료기반/유료표준 원문비인용)를 페이지마다 footer에 명시적으로 구분 표기.
